This study applies machine learning techniques to classify bacterial exotoxins based on their functional types and target specificity.
We organize methodology into several stages: (1) data collection and curation, (2) dataset preprocessing, including redundancy reduction, (3) feature extraction from protein sequences and predicted structures using protein language models, (4) model development and training using various machine learning algorithms, and (5) model evaluation using appropriate metrics and controls.

First, we collect and analyze primary sequences using descriptive statistics to understand key sequence characteristics.
Next, we preprocess the dataset using redundancy reduction techniques to generate a non-redundant set of sequences.
Protein language models are then used to generate numerical embeddings that capture meaningful sequence representations.
Then, dimensionality reduction using Principal Component Analysis (PCA) is applied to the embeddings.
The processed embeddings are subsequently used to train machine learning models, which are finally evaluated using performance metrics for binary and multiclass classification tasks.

This methodology enables the development and evaluation of ExoType to classify exotoxins by functional type and ExoTarget to predict their target specificity as effective tools for bacterial exotoxin classification.

\section{Data Collection and Curation}

Bacterial toxins protein sequences were collected from public sequence databases such as UniProt and \gls{NCBI}, as described previously by Krueger et al. \cite{kruger2024toxin}.
The dataset was curated and labelled by selecting proteins from bacterial pathogens based on their host specificity by PD. Dr. Luisa F. Jimenez-Soto.

\subsection{Composition of Exotoxin Types and Targets}

In this process, proteins from bacterial pathogens that infect insects, plants, and other bacteria were categorized as non-vertebrate targets, whereas those affecting vertebrates—including fish, amphibians, birds, reptiles, and mammals—were classified as vertebrate targets.
The target categories consist of 1,863 vertebrate-targeting exotoxins and 629 non-vertebrate-targeting exotoxins.

Similarly, bacterial exotoxins were categorized based on their mode of action and how they exert their effect on the host.
The classification scheme of functional types, along with the corresponding sequence counts, is as follows:
\begin{description}
	\item[Type I:] Membrane-transducing toxins (42 entries).
	\item[Type II:] Pore-forming toxins (169 entries, including Type II and Type II PFT bacteria).
	\item[Type III:] Intracellular toxins (2,148 entries, including both Type III and Type III Control).
	\item[Type IV:] Toxins that degrade the extracellular matrix (28 entries).
\end{description}

In addition, there are 104 sequences that do not belong to any of the four defined types (classified as \textbf{Unknown} in the dataset).

\subsection{Dataset Structure and Pre-processing}

The curated dataset was organized in a \textit{csv} file, which contains columns for \texttt{bacterial species}, \texttt{exotoxin types}, and \texttt{specific targets}. This labelled data was used to annotate the input files for building a predictive model for bacterial exotoxin classification. The corresponding protein sequences are stored in a FASTA file, where each record includes an \texttt{exotoxin ID} and its associated protein sequence. The \textit{csv} and FASTA files were merged using their common IDs, resulting in a fully labelled dataset that contains bacterial exotoxin sequences along with their respective types and targets. The data preprocessing was implemented using the Python script (version 3.13.1).

Subsequently, a Python script was employed to eliminate sequences annotated as ``partial'' or ``fragment'' in their FASTA headers, thereby removing incomplete sequences.

\section{Descriptive Statistical Analysis of Sequences}
\label{section:descriptive_statistical_analysis}

The calculation of the statistical properties of protein sequences is essential for understanding of the characteristic properties of biological data and the identification of potential biases in the data set \cite{durbin1998biological}.
Descriptive statistical analysis gives insights into the fundamental sequence properties, such as length distributions and hydrophobicity.

We propose to conduct this analysis using custom Python scripts, incorporating key libraries such as Biopython (version 1.85) \cite{cock2009biopython} for sequence handling, NumPy (version 2.2.2) for numerical computations, and Matplotlib (version 3.10.0) for visualization.

\subsection{Mean Sequence Length}
\label{subsection:mean_sequence_length}

Variability in sequence length is an important factor that can have an impact on the training of machine learning models.
The following formula is used to calculate the mean sequence length, denoted by $\mu$:

\begin{equation}
	\mu = \frac{1}{N} \sum_{i=1}^{N} L_i,
	\label{eq:mean_sequence_length}
\end{equation}
where:
\begin{itemize}
	\item $\mu$ is the mean sequence length,
	\item $N$ is the total number of sequences in the dataset,
	\item $L_i$ represents the length of the $i^\text{th}$ sequence.
\end{itemize}


\subsection{Hydrophobicity Analysis}
\label{subsection:hydrophobicity}

Hydrophobicity affects protein structural stability, folding, and interactions with cellular components \cite{Baldwin2007}.
The average hydrophobicity $H$ of each sequence was computed using the Kyte-Doolittle scale \cite{Kyte1982}:

\begin{equation}
	H = \frac{1}{L} \sum_{i=1}^{L} H_i,
	\label{eq:hydrophobicity}
\end{equation}
where:
\begin{itemize}
	\item $H$ is the average hydrophobicity of the sequence,
	\item $L$ is the sequence length,
	\item $H_i$ is the hydrophobicity score of the $i^\text{th}$ amino acid.
\end{itemize}

Explained hydrophobicity and sequence length analyses can reveal statistical outliers and potential biases in the dataset.

\section{Redundancy Reduction}
\label{section:redundancy_reduction}

Machine learning models trained on redundant sequences can become biased toward overrepresented classes, reducing their generalizability.
To mitigate this, we apply a redundancy reduction procedure to the dataset using MMseqs2 \cite{steinegger2017mmseqs2} in two steps:


\begin{enumerate}
	\item \textbf{Exact Duplicate Removal:}  
	Protein sequences in FASTA format are first converted into an MMseqs2 database.
	An initial clustering is then performed using a 100\% sequence identity threshold to remove exact duplicate sequences.
	This step prevents duplicate entries from being in the dataset.
	
	\item \textbf{Clustering of Similar Sequences:}  
	In the next step, sequences are clustered using a 30\% sequence identity threshold.
	This grouping of similar sequences enhances the diversity of the dataset by reducing redundancy.
\end{enumerate}

We exclude the redundant sequences from the training set. The entire workflow is automated using a Python script.


\section{Prediction of 3D Protein Folds}
\label{section:protein_folds}

After redundancy reduction, we employ AlphaFold2 \cite{Jumper2021} to predict the 3D structures of bacterial toxin proteins.
The structural confidence of these predicted protein folds is quantified using per-residue \textit{predicted Local Distance Difference Test} (pLDDT) scores.
The \gls{pLDDT} scores are used to assess the quality of the predicted 3D structures for exploratory purposes without imposing a strict acceptance threshold.

To evaluate the quality of the generated protein folds, we develop a computational pipeline to extract per-residue \gls{pLDDT} scores from the predicted structures.
We use \texttt{Biopython} library \cite{cock2009biopython} to parse AlphaFold2-generated Protein Data Bank (PDB) files.
This pipeline follows the following steps:
\begin{enumerate}
	\item Iterate through each \gls{PDB} file generated by AlphaFold2, where each file corresponds to a single predicted protein structure.
	\item Parse the structural information of each protein model using \texttt{Biopython}'s \texttt{PDBParser} module \cite{Cock2009}.
	The \gls{pLDDT} score is stored in the B-factor field of each atom; since all atoms within a residue share the same pLDDT value, a single representative score per residue is used.
\end{enumerate}

This analysis ensures that the predicted 3D structures are robust and suitable for following analyses, such as embedding generation and machine learning model training in the next sections.

\section{Preparation of Training and Test Datasets}
\label{section:training_test_set}

To address both sequence similarity biases and the limited size of our dataset, we apply two different data-splitting strategies.
In both methods, the training set is used for model development via K-fold cross-validation (for training, validation, and hyperparameter tuning),
while the test set is exclusively used for the final performance evaluation of the model.


\subsection{Method 1: Redundancy Reduction Based Data Splitting}

After redundancy reduction with a sequence identity threshold of 30\%, sequences that exhibit more than 30\% similarity to any other sequence are excluded from the training set and instead assigned to the test set.
This approach ensures that the training set contains unique, non-redundant sequences.
Therefore, it minimizes potential bias due to redundant sequences and enhances the generalizability of the trained models, while still utilizing the full dataset for evaluation.

\subsection{Method 2: Standard Random Data Splitting}

In the second approach, we perform a stratified random split on the non-redundant dataset.
Using Scikit-Learn’s \texttt{train\_test\_split} function (version 1.6.1) with a fixed random state of 42 for reproducibility, the dataset is partitioned into 80\% training and 20\% test sets \cite{pedregosa2011scikit}.

\section{Embedding Generation}
\label{section:embedding_generation}

Protein embeddings are generated from both protein sequences and protein folds, utilizing dedicated protein language models: \gls{ProtT5} and \gls{ProstT5}.
Both sequence-based and fold-based protein embeddings have 1024 dimensions, and default settings are used for both models.

For sequence-based protein embedding generation, we employ the \gls{ProtT5} language model to generate embeddings for each protein sequence which encodes sequence-specific features \cite{elnaggar2021prottrans}.
The embeddings are generated using a script in Google Colab notebook (\texttt{embed\_ProtT5.ipynb}), which was executed in November 2024.

To incorporate structural information, embeddings are also generated using the \gls{ProstT5} language model, which is trained to encode 3D structural features from protein folds \cite{heinzinger2023prostt5}.
These fold-based embeddings are produced via a separate Google Colab notebook (\texttt{ProstT5.ipynb}), executed in December 2024. The Google Colab notebook links can be found in the Appendix.

The generated embeddings serve as inputs for subsequent dimensionality reduction and machine learning model training steps.


\section{Dimensionality Reduction}
\label{section:dimensionality_reduction}

The embedding generation process, described in Section \ref{section:embedding_generation}, results in high-dimensional feature vectors (1024 dimensions for both \gls{ProtT5} and \gls{ProstT5}).
While these embeddings capture rich information, their high dimensionality can lead to the "curse of dimensionality" in subsequent machine learning tasks, particularly given the limited size of our training set \cite{bishop2006pattern}.
This increases the risk of overfitting the training data and potentially reducing model generalizability.

To address these potential problems and reduce the complexity of the high-dimensional embedding vectors, we apply Principal Component Analysis (PCA) \cite{greenacre2022pca}.
\gls{PCA} transforms the original high-dimensional embeddings into a lower-dimensional space while keeping the most relevant information and variance within the data. \cite{greenacre2022pca}.
This can be viewed as a form of regularization technique, which simplifies the input feature space and reduces noise.


The specific number of principal components retained is determined empirically based on a series of experiments, evaluating the cumulative explained variance ratio as a function of the number of components.  
Our goal is to select a number of components that balance dimensionality reduction with information retention.
The point at which adding additional components increases complexity more than explained variance is chosen as the number of reduced dimensions.
This approach ensures that we retain the most significant components that capture the majority of the variance in the data while minimizing the risk of including less informative components that could contribute to noise.
These reduced-dimensionality vectors, representing the projections of the original embeddings onto the selected principal components, are then used as input for subsequent model training.

\section{Model Training}
\label{section:ml_training_evaluation}

After dimensionality reduction, the reduced-dimensionality embeddings are used to train machine learning models for both exotoxin type and target classification.

\subsection{Model Selection and Hyperparameter Tuning}
We select the following machine learning models because of their diverse approaches to classification and their strong performance in bioinformatics applications:

\begin{description}
	\item[Random Forest  \cite{Breiman2001}:] An ensemble machine learning algorithm that combines the prediction of multiple decision trees.
	\item[Logistic Regression  \cite{Cox1958}:] A linear machine learning model that uses a sigmoid function as an activation function to predict the probability of a binary outcome.
	\item[Support Vector Machine (SVM)  \cite{Cortes1995}:] A supervised machine learning algorithm that classifies data points by maximizing the margin between classes in the higher-dimensional space with the estimated optimal hyperplane.
	\item[K-Nearest Neighbors (KNN)  \cite{Guo2003}:] A supervised machine learning algorithm that classifies a data point based on the majority class of its closest k-nearest neighbors in the feature space.
\end{description}

To optimize model performance, we perform hyperparameter tuning using GridSearchCV from scikit-learn (version 1.6.1) \cite{pedregosa2011scikit}.
GridSearchCV investigates a predefined range of hyperparameter values, applying k-fold cross-validation for each combination and selecting the combination best performance results based on a chosen evaluation metric (see Section \ref{section:model_evaluation} for details on the evaluation metric) \cite{liashchynskyi2019gridsearchrandomsearch}.  
This process ensures that the chosen hyperparameters give the highest scores of the evaluation metric while avoiding overfitting to a training set.
Thus, the models are more likely to generalize well to unseen data, which is especially important in our study given the limited size of the training dataset.
Some hyperparameters are set to the default values commonly used in the scientific literature.

\subsection{Hierarchical Predictor}
\label{subsubsection:hierarchical_model}

To address the class imbalances in the exotoxin type dataset and improve overall classification performance, we propose a custom hierarchical predictor.
As described previously, the dataset exhibits a highly skewed distribution.
Type III toxins dominate with over 90\% of the overall data types while other types are significantly less frequent.
This imbalance can lead to models that are biased towards the majority class (Type III) and perform poorly on other minority classes, even after the techniques used in the thesis such as dimensionality reduction.
The proposed hierarchical approach directly tackles this challenge.


This hierarchical predictor employs a two-stage classification process, grouping and separating classification tasks to mitigate the effects of imbalance:

\paragraph{First Stage: Broad Group Classification.} The first-stage classifier of the hierarchical predictor is trained to distinguish between three broader groups:

\begin{itemize}
	\item Group 1: Type I and Type IV toxins (combined)
	\item Group 2: Type II and Type III toxins (combined)
	\item Group 3: Unknown
\end{itemize}

This initial grouping creates more balanced classes for the first-stage classifier.
Combining Type I with Type IV (42 + 28 = 70 entries) and Type II with Type III (169 + 2148 = 2317 entries) results in a less severe, though still present, imbalance.
This allows the first-stage classifier to learn the distinguishing features between these groups of toxins without being overwhelmed by the dominance of Type III.


\paragraph{Second Stage: Separate Classification.} Following the first-stage classification, separate classifiers are trained and applied within each of the combined groups (Group 1 and Group 2).  

\begin{itemize}
	\item  A classifier is trained specifically to distinguish between Type I and Type IV toxins, using only the data points classified as Group 1 by the first-stage classifier.
	\item  Another classifier is trained to distinguish between Type II and Type III toxins, using only the data points classified as Group 2 by the first-stage classifier.
\end{itemize}

In total, this hierarchical architecture has three distinct classifiers: one for the initial broad grouping and two for the following separate second-stage classification within the combined groups.

\section{Model Evaluation}
\label{section:model_evaluation}

To assess model performance and generalizability, we perform several evaluation strategies.
First, all models are trained and also evaluated with cross-validation in this study.
We use the \gls{MCC} \cite{matthews1975comparison} as our primary performance metric because of its strength in imbalanced datasets.
We also explore Precision-Recall curves to understand the model performance.
Finally, we implement a \gls{BLAST}-based baseline comparison and a negative control using scrambled sequences.

\subsection{Matthews Correlation Coefficient (MCC)}

The  \gls{MCC}) \cite{chicco2020advantages} is the used primary performance metric due to its suitability for imbalanced datasets, which is a key characteristic of our exotoxin type data.
\gls{MCC} is a balanced measure for both binary and multiclass classification, even with imbalanced classes.
The standard \gls{MCC} formula is only valid for binary classification.
Since we also need multiclass classification, we use the revised multiclass \gls{MCC} in our study for the evaluation of the performance of ExoType predictors.
Table \ref{tab:mcc} provides the formulas for both binary and multiclass \gls{MCC}.

\begin{table}[h!]
	\centering
	\small
	\begin{tabular}{|l|p{10cm}|}
		\hline
		\textbf{Binary class MCC} &
		\[
		\text{MCC} =
		\frac{TP \times TN - FP \times FN}
		{\sqrt{(TP + FP)(TP + FN)(TN + FP)(TN + FN)}}
		\]
		\\
		\hline
		\textbf{Multiclass MCC} &
		\[
		\text{MCC}_{\text{multi}} =
		\frac{
			\sum_{k=1}^{K}\sum_{l=1}^{K}\sum_{m=1}^{K}
			\bigl(C_{kk}\,C_{lm} - C_{kl}\,C_{mk}\bigr)
		}{
			\sqrt{
				\sum_{k=1}^{K}
				\Bigl(\sum_{l=1}^{K} C_{kl}\Bigr)
				\Bigl(\sum_{l=1}^{K} C_{lk}\Bigr)
				- \sum_{k=1}^{K} C_{kk}^{2}
			}
		}
		\]
		\\
		\hline
	\end{tabular}
	\caption{Matthews Correlation Coefficient (MCC) in binary and multiclass settings.}
	\label{tab:mcc}
\end{table}


\subsection{Precision-Recall and AUPRC}

In addition to \gls{MCC}, we assess model performance using \gls{PR} curves and the \gls{AUPRC}).  
 \gls{PR} curves are particularly useful for evaluating models on imbalanced datasets, as they put more focus on the performance of the positive (minority) classes \cite{saito2015precision}.
On the other hand, Receiver Operating Characteristic (ROC) curves can sometimes present overly optimistic performance evaluation for the imbalanced dataset with a highly dominant class \cite{saito2015precision}.

The Precision measures the proportion of correctly predicted positive instances among all positively predicted instances, while the Recall measures the proportion of correctly predicted positive instances among all actual positive instances.
\gls{AUPRC} provides a summary of both metrics that highlight the trade-off between Precision and Recall.
For multiclass classification, we utilize a one-vs-rest strategy, computing  \gls{PR} curves and  \gls{AUPRC} values for each class individually against the remaining classes.
The final \gls{AUPRC} scores are obtained by averaging the values across all classes.

\subsubsection{Cross-Validation}

We employ 5-fold cross-validation to obtain a robust estimate of model performance on unseen data without overfitting.
Cross-validation divides the training set into five equal-sized folds.
This approach trains the model five times by using each fold as the validation set while using the rest of the remaining four folds as a training set, thereby reducing the risk of overfitting. Then, performance metrics (\gls{MCC} and \gls{AUPRC}) are averaged across all folds.


\subsection{Negative Control: Scrambled Protein Sequence Embeddings}
\label{subsection:negative_control_scrambled_embeddings}

To verify the machine learning models capture meaningful biological information, we implement a negative control.
We randomly shuffle protein sequences while preserving the amino acid composition and then generate embeddings from these scrambled protein sequences.
This ensures that any observed performance is due to the order of the amino acids in the sequence and not simply their presence or absence.

These scrambled sequences are then processed through the same embedding pipeline (using \gls{ProtT5} and \gls{ProstT5}) and dimensionality reduction steps as the original sequences, creating a negative control dataset.
This provides a crucial baseline against which to compare the performance of models trained on the original dataset.


\subsection{BLAST-Based Baseline}
\label{subsubsection:blast_predictor}

As a baseline for comparison, we also employ BLAST (Basic Local Alignment Search Tool) \cite{Altschul1990} for sequence similarity analysis.
It is widely used tool for finding regions of similarity between biological sequences.
This works as a traditional, non-machine learning baseline for evaluation of our embedding-based machine learning models.
Comparing our machine learning models to this \gls{BLAST} baseline allows us to determine if the learned embeddings capture information beyond simple sequence similarity.

The  \gls{BLAST} based prediction in our study is performed as follows:

\begin{enumerate}
	\item A \gls{BLAST} database is created using only the protein sequences from the training set.
	
	\item Each protein sequence in the test set is used as a query against this \gls{BLAST} database.
	
	\item For each query sequence, we determine the predicted class (ExoType or ExoTarget)according to the top hit returned by \gls{BLAST} (i.e., the sequence in the training set with the highest alignment score).
\end{enumerate}

\gls{BLAST} compares a query sequence to a database of sequences and calculates an alignment score reflecting their similarity.
Our baseline \gls{BLAST} predictor uses this score to assign the query sequence to the class of its most similar sequence in the training data.
